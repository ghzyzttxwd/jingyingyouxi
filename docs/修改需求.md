# 修改需求 V0.1

## 1. 时间倍率

目标：提高游戏内可用的时间加速倍率。

### V0.1 已实施

- 保留原有按钮与“普通/高倍”状态结构，不改 UI。
- 已定位 `TimeManager.时间流逝逻辑`。
- 原版普通状态阈值约 `1.0s`，高倍状态阈值约 `0.5s`，即约 2 倍。
- 测试版把高倍阈值改成 `0.125s`，因此高倍状态约 **8 倍**。
- 普通速度保持不变。

验收重点：
- 高倍状态明显快于原版。
- 日期、订单、建筑/经营逻辑不停止、不异常跳过。

## 2. 订单数量随企业等级成长

目标：企业等级越高，订单数量整体越高。

### V0.1 已实施

已定位：
- `DingDanManager.订单发放逻辑`
- `DingDanData.新增订单(物品序号, 数量, 单价, 剩余期限)`
- `PlayerData.获取公司等级()`

测试公式：

```text
最终数量 = 原数量 + 原数量 × (公司等级 - 1) / 5
```

约等于每升 1 级在原订单数量基础上增加 20%：

- Lv1：1.0×
- Lv2：1.2×
- Lv5：1.8×
- Lv10：2.8×
- Lv20：4.8×

只修改订单“数量”，不主动改品类、单价和期限。该成长曲线属于第一版测试参数，真机确认后可继续调。

验收重点：
- 高等级订单数量明显更高。
- 金额仍跟随数量正确计算。
- 不出现 0、负数、溢出或离谱爆量。

## 3. 广告奖励直接领取

目标：原本需要激励广告的奖励按钮，改为不播放广告并直接进入原奖励发放路径。

### V0.1 已实施

已定位：
- `RewardManager.播放广告()`
- `RewardManager.SendReward()`

当前 patch：

```text
RewardManager.播放广告()
    ↓
直接跳转 RewardManager.SendReward()
```

不删除第三方广告 SDK，只绕过实际广告播放过程，尽量保留原游戏自己的奖励 ID、奖励数值和发放逻辑。

验收重点：
- 点击奖励按钮不拉起广告。
- 奖励只发一次。
- 不黑屏、不卡死、不出现重复回调。

## 4. 当前测试包范围

- APK 原版本：`1.0.9` / versionCode `10`
- Unity：`2022.3.62f2c1`
- IL2CPP metadata：v31
- 当前 patch：仅 `arm64-v8a`
- `armeabi-v7a` 暂保留原版；现代 64 位 Android 设备会优先加载 arm64。
- APK 已重新打包，`resources.arsc` 保持未压缩并恢复 4-byte alignment。
- 测试 APK 使用 APK Signature Scheme v2 重新签名。

已通过静态/本地检查：
