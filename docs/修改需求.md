# 修改需求 V0.1

## 1. 时间倍率

目标：提高游戏内可用的时间加速倍率。

当前优先方案：先保留原有按钮和交互，只替换高倍速逻辑，避免第一版同时改 UI 与状态结构。

待定位：
- `TimeManager` 中倍率状态字段
- `切换时间速度` 对应 IL2CPP 方法
- 时间推进实际使用的倍率常量/分支
- 倍速文案生成逻辑

验收：
- 普通速度不受影响
- 高倍速明显高于原版
- 日期、订单、建筑/经营逻辑不因倍率修改而停止或异常

## 2. 订单数量随企业等级成长

目标：企业等级越高，订单数量整体越高。

第一版原则：
- 不改变订单品类、单价、期限等其他规则
- 仅对生成出的“数量”增加等级成长系数
- 成长公式做成可调整参数，避免以后重新逆向

待定位：
- `DingDanManager` 的订单生成/发放调用链
- `DingDanData` 的新增订单与数量写入位置
- 企业等级读取入口

验收：
- 同等条件下，高等级企业订单数量明显高于低等级
- 不出现负数、0、整数溢出或极端爆量
- 金额计算仍与数量一致

## 3. 广告奖励直接领取

目标：原本需要激励广告的奖励按钮，改为不播放广告并直接进入原奖励发放路径。

第一版原则：
- 尽量保留原奖励逻辑
- 不主动删除整套广告 SDK，避免初始化依赖导致崩溃
- 优先改游戏自身的广告调用入口，而不是改第三方 SDK

待定位：
- `RewardManager.播放广告`
- `RewardManager.SendReward`
- 各奖励按钮到 RewardManager 的调用链

验收：
- 点击对应按钮不拉起广告
- 奖励只发放一次
- 原有奖励种类与数值不被误改
- 无卡死、黑屏、重复回调

## 版本策略

V0.1 先完成最小可用修改；确认真机稳定后，再考虑增加多档倍率、可配置成长曲线等功能。
