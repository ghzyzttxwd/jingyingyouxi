# V0.3 TapTap 登录修复

## 现象

V0.2 已能正常安装，但点击 TapTap 登录后提示：

`TapSDK: 包名、签名错误。详见 ErrLog`

## 原因

APK 修改后必须重新签名。TapTap 登录会校验应用包名与开发者在 TapTap 后台登记的原始签名证书；修改版没有原开发者私钥，因此无法继续以原签名完成 TapTap 登录。

这不是 V0.2 APK v2 签名格式错误；V0.2 已通过 Android 安装器并成功启动，说明 APK 自身签名已经可用。错误来自 TapTap SDK/平台对应用身份的额外校验。

## 游戏自身的离线分支

逆向 `TapTapLoginManager` 后确认：

- `TapTap登录状态` 实例字段位于 `[TapTapLoginManager + 0x40]`。
- `TapTapLoginManager.<Start>d__23.MoveNext` VA：`0x132EB60`。
- `0x132EBEC` 读取 `[X20 + 0x40]`。
- `0x132EBF0` 原指令为 `CBZ W8, 0x132ED3C`。
- 当该状态为 false 时，`0x132ED3C` 分支不会初始化 TapSDK，并会取得 `GameUIManager.Instance.开始界面_登录按钮显示`（实例字段约 `+0x98`）后执行 `SetActive(false)`。

因此游戏本身已经存在“关闭 TapTap 登录”的路径。

## V0.3 修改

将：

`0x132EBF0: CBZ W8, 0x132ED3C`

改为：

`0x132EBF0: B 0x132ED3C`

效果：修改版启动时无条件走游戏原有的离线分支，跳过 TapSDK 初始化并隐藏 TapTap 登录按钮。

该修改不伪造 TapTap 账号，也不尝试绕过 TapTap 服务端的账号认证。

## 签名

V0.3 继续使用 V0.2 的同一测试签名证书，目的是允许已安装 V0.2 的设备直接尝试覆盖升级。

- APK v2 自检通过。
- ZIP `testzip()`：无损坏。
- APK SHA-256：`4dcc4498ff7ae5a2fbbd67aabc1ba936ad5bfcf0efd8b5aac911eb902eee661b`。
