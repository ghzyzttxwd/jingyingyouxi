# V0.1 安装失败与 V0.2 修复记录

## 现象

Android Package Installer 报错：应用未安装 / 软件包可能无效。

## 已确认根因

V0.1 自写 APK Signature Scheme v2 编码器在 `0x7109871a` value 中漏写了一层必需的 length-prefix。

正确层级应为：

```text
v2 value
└─ length-prefixed signer sequence
   └─ length-prefixed signer
      ├─ length-prefixed signed data
      ├─ length-prefixed signatures
      └─ length-prefixed public key
```

V0.1 实际只有 `length-prefixed signer`，缺少最外层 `signer sequence` 的长度字段。因此内部自检虽然可以按同一错误结构解析并验证 RSA/content digest，但 Android 按标准结构解析时会把字段错位，最终拒绝安装。

## V0.2 修复

- `scripts/apk_v2_sign.py` 已补上最外层 signer sequence length-prefix。
- 自检解析器同步改为按标准双层 LP 解析。
- 修复后的嵌套长度结构已与原版 APK 的 v2 block 逐层对比。
- ZIP 完整性重新验证通过。
- v2 RSA PKCS#1 v1.5 + SHA-256 签名重新验证通过。
- v2 content digest 重新计算一致。

V0.2 APK SHA-256：

```text
55fc22117867aa6297a7a56392ff6fd11e49c9016f3c4073c957f42e7583e618
```

v2 content digest：

```text
695b0ffc53f0f8b12a7e17a0c278ba016f37308e7f29d54b216644eb46e92875
```

## 仍需注意

V0.2 使用新的自签名证书。若手机上仍安装官方原版 `com.dcyxgzs.wdjt`，Android 不允许用不同签名直接覆盖同包名应用。此时即使 APK 本身有效，也会安装失败。

有重要存档时不要直接卸载原版；可另做改包名的并存测试包。
