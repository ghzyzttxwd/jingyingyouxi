## Assembly-CSharp CodeGenModule

在 arm64 `libil2cpp.so` 中已定位 `Assembly-CSharp.dll` 对应的 `Il2CppCodeGenModule`：

- module struct VA：`0x27ADB48`
- method pointer count：`0xBD3`（3027）
- method pointer table VA：`0x2956958`

因此可以按 MethodDef token 的 RID 直接还原本程序集方法地址。

## 1. 广告奖励

`RewardManager.播放广告()` 与 `RewardManager.SendReward()` 都是实例无参方法。

第一版采用最小 patch：

```text
RewardManager.播放广告 entry
    ↓
直接 B RewardManager.SendReward
```

这样保留原游戏的奖励类型、奖励数量和 `RewardManager` 当前 ID 状态，只跳过第三方广告播放链路。

Patch：

- `0x12CA3EC`: 原函数首指令 → `B 0x12C8A24`

原 `播放广告` 函数入口之后的代码因此不可达，第一版将其中一小段作为订单成长 trampoline 使用。

## 2. 时间倍率

`TimeManager.时间流逝逻辑` 已确认不是直接设置 Unity `Time.timeScale`，而是按内部计时阈值推进回合/日期。

```text
普通状态阈值：1.0 秒
原高倍状态阈值：0.5 秒
```

原版通过字段 `[TimeManager + 0x21]` 的布尔状态在 `1.0` 与 `0.5` 之间选择，因此原高倍状态实际约为 2 倍。

第一版测试 profile：

- `0x132FAD4`: `FMOV S1,#0.5` → `FMOV S1,#0.125`

即原高倍状态改为约 **8倍**。普通状态仍保持 1.0，不改原按钮/状态结构。

## 3. 订单数量成长

`DingDanData.新增订单` 参数已经从 metadata 确认：

```text
新增订单(物品序号, 数量, 单价, 剩余期限)
```

在 `DingDanManager.订单发放逻辑` 中，调用点：

- `0x12F7FE0`: `BL DingDanData.新增订单`

调用前寄存器：

```text
X0 = DingDanData instance
W1 = 物品序号
W2 = 数量
W3 = 单价
W4 = 剩余期限（当前生成处为 60）
X5 = MethodInfo（null）
```

已定位 `PlayerData` 静态实例获取链以及 `PlayerData.获取公司等级()`。

第一版测试 profile：

```text
最终数量 = 原数量 + 原数量 × (公司等级 - 1) / 5
```

约等于每升 1 级在原订单数量基础上增加 20%：

- Lv1：1.0×
- Lv2：1.2×
- Lv5：1.8×
- Lv10：2.8×
- Lv20：4.8×

实现方式：把 `0x12F7FE0` 的原 `BL 新增订单` 改为 `BL trampoline`；trampoline 读取公司等级、只改 `W2` 数量，再调用原 `新增订单`。

## 4. APK 重打包与签名

已完成：

- 替换 `lib/arm64-v8a/libil2cpp.so`
- 移除原 APK 的旧 `META-INF` v1 签名文件
- 保持各 entry 原压缩方式
- `resources.arsc` 保持 `stored`（不压缩）
- 为 `resources.arsc` 恢复 4-byte alignment
- 写入 APK Signature Scheme v2 signing block
- 算法：RSA PKCS#1 v1.5 + SHA-256（algorithm ID `0x0103`）

测试 APK：`jingyingyouxi-v0.1.apk`

- APK SHA-256：`b83b85054cc1d0bc13caf5002ffbb1556508210470b51d4cc2b7e24a15d36267`
- patch 后 arm64 `libil2cpp.so` SHA-256：`979458694197fe31d33ebb5b0d74f92f0930d250809f610b80e156794045b221`
- v2 content digest：`695b0ffc53f0f8b12a7e17a0c278ba016f37308e7f29d54b216644eb46e92875`

本地 v2 自检已验证：

- signing block 两端 size 一致
- v2 ID `0x7109871a` 可解析
- signed-data RSA 签名验证通过
- certificate SPKI 与 signer public key 一致
- 重新计算 APK v2 content digest 与签名块保存值一致
- ZIP `testzip()` 无损坏
