# V0.4 修复记录

## 用户真机反馈

V0.3 已可进入游戏，但点击“观看广告获取倍速权限”等激励广告入口会直接退回桌面；右上角仍显示 `2.0X`。

## 根因

V0.1-V0.3 把 `RewardManager.播放广告()` 的入口直接改成了 `B RewardManager.SendReward()`。

进一步核对调用约定后确认：调用 `播放广告()` 时真正的 `RewardManager` 实例由上层 wrapper 保存在 `X19`；`X0` 在进入 `播放广告()` 前已经被临时辅助函数改写。`SendReward()` 则把 `X0` 当作 `RewardManager this` 使用。因此旧补丁把无效指针传给 `SendReward()`，触发 native 闪退。

V0.4 修复为：

```text
RewardManager.播放广告 entry:
    MOV X0, X19
    B   RewardManager.SendReward
```

所有已定位的奖励 ID 1-8 都会汇入同一个 RewardManager wrapper，因此该修复覆盖现有主要激励广告入口。

## 倍速

- 实际高倍阈值仍为 `0.125s`，即相对普通 `1.0s` 约 8 倍。
- `PlayerData` 的倍速权限 getter 改为直接返回 `true`，点击倍速按钮不再进入“看广告获取权限”确认链。
- `global-metadata.dat` 中唯一的 `2.0X` 字面量改为 `8.0X`，同步界面显示。

## 其他保留修改

- 订单数量随公司等级成长。
- TapTap 登录继续走游戏内置离线分支。
- V0.4 APK 使用与 V0.2/V0.3 相同的测试签名证书，便于直接覆盖安装。

## 验证状态

静态验证已完成：

- Reward bypass 反汇编确认 `MOV X0,X19 -> B SendReward`。
- 倍速权限 getter 反汇编确认 `MOV W0,#1 -> RET`。
- 高倍阈值确认 `FMOV S1,#0.125`。
- TapTap 离线分支保留。
- ZIP 完整性检查通过。
- APK v2 签名自检通过，并使用与 V0.3 相同证书。

仍需真机验证广告奖励、倍速显示/行为和订单成长。
